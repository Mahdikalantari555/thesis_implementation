# Design — mini-research-dataset

## 1. Zarr version decision (verified)

Benchmark (2026-11-24, real shape (538,7,36,14) float16, 1 farm):
- v3 write 0.89 s, read 1.30 s. v2 write 1.47 s, read 1.37 s.
- Both round-trip through xarray 2026.7 with `consolidated=True`.
- v3 consolidated metadata is **not** part of the Zarr v3 spec → portability warning across implementations; v2 consolidated metadata is stable and universally read.

**Decision: use zarr v2 for the mini store** (and keep v2 for legacy stores). Rationale: portability + compatibility with existing xarray pipelines outweighs the ~0.6 s/farm write difference. Migration to v3 can be done later behind a reader shim; no blocker.

## 2. Date source (critical correction)

- `stats.zarr["time"]` holds day-numbers since 2013-01-01 (0, 49, 56, …). Converting these to calendar dates produces phantom dates (e.g. 2013-01-01) that do not correspond to any acquisition. The existing `build_raw_satellite_subset.py` does this conversion → **latent bug**.
- **Correct source:** `scene_inventory.parquet["acquisition_date"]` = 538 real dates (2013-03-30 → 2026-09-10), all with a scene dir under `Data/Metric/scenes/`.
- `weather_aligned.parquet` has 539 dates = the 538 scene dates + `2022-08-07` (no scene). The mini store keeps the 538 satellite dates; weather is joined by date (left join), 2022-08-07 simply has no satellite row.

## 5. Weather features

- Keep all 57 existing columns verbatim (no drop).
- Add `gdd_daily` (base 10 °C from T min/max) and `heat_stress_hours` (hourly T > 35 °C from `point_01_raw_hourly.parquet`), as new columns.
- Feature groups defined in `weather_features.json`: `spectral_only`, `weather_core`, `weather_rolling`, `weather_all`, `weather_plus_derived`. Ablation selects a group by name.
- Causality: rolling windows already past-only; derived features computed from data available up to the observation date.

## 6. Spatial representation

- Pixel-level: per-pixel 7-band vectors.
- Patch-level: configurable sizes (default 3,5,7; no upper bound). Extraction uses `in_field` mask; patches with < threshold valid in-field pixels are dropped or masked (configurable). Valid-patch count reported per farm/date.
- Full-field: whole farm bbox (36×14) with `in_field` mask.
- Padding strategy configurable: none / reflect / zero, with mask propagation.

## 7. Temporal representation

- Real acquisition date + Δt (days since previous observation) stored alongside values. Irregular cadence must not be assumed regular.
- Supported: full series, fixed sliding window (length/stride config), seasonal/growth-cycle windows, variable-length, temporal sampling.
- Growth-cycle windows derived from phenology on multi-band curve (NDVI+SAVI+LST+GDD), not NDVI alone.

## 8. Protocols (configurable, all supported)

1. **Single-Farm:** train R12-08 → test R12-06, R12-10.
2. **Leave-One-Farm-Out:** 3 rotations (train 2, test 1).
3. **Intra-Farm Temporal:** time split within one farm.

No protocol is privileged; selected via config. Train-only normalization fit enforced.

## 9. Seasons / coverage / leakage review

- Monthly coverage: 27–64 scenes/month across 2013–2026; fairly uniform. No month is empty.
- Dates per year: 23 (2022) – 70 (2024). 2026 partial (Jan–Sep).
- Sugarcane cycle in Khuzestan: plant Mar–Apr, harvest Dec–Jan. A 2025–2026 holdout covers complete + partial cycles.
- **Leakage risks:** (a) weather rolling windows are already causal (verified); (b) temporal split must be by date not row index; (c) with only 3 farms, farm-holdout is the real generalization test; (d) 2026 partial year means a "last 2 years" holdout is slightly unbalanced.
- **Decision:** do not hard-code 2025–2026 as the validation split. Make the temporal holdout configurable (default: last complete season boundary detected from phenology), require justification in each run's report. Document the chosen boundary + n + date range.

## 10. Model scope

All architectures from the user's spec remain in the framework: MLP-AE, GRU-AE, LSTM-AE, CNN-AE, ConvLSTM-AE, Mamba-AE, CNN-Mamba, Barlow Twins, JEPA. None removed for CPU reasons. Execution placement:
- Laptop (CPU): MLP-AE, GRU-AE, LSTM-AE, CNN-AE, Barlow Twins (small).
- Colab (T4): ConvLSTM-AE, Mamba-AE, CNN-Mamba, JEPA, and larger variants.
Same scripts, `--device auto`. Param budget ≤ 250k for laptop runs (AGENTS.md §7); Colab runs may exceed.

## 11. Tracking & HPO

- MLflow: one experiment per protocol, runs tagged with farm, protocol, model, spatial/temporal repr, weather group, seed, git SHA.
- Optuna: HPO studies with equal trial budget per architecture; controlled comparison runs with fixed (non-HPO) configs first, then HPO.
- Reports: metrics with mean±std over seeds, n, date range, seeds, device, wall time, git SHA, data_source, split hashes.
