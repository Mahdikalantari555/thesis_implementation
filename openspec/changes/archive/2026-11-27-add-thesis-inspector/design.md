# Design

## Context

See `proposal.md` for motivation and `specs/thesis-inspector/spec.md` for the behavior contract. The repository targets Python 3.11+, uses `reports/dev/<run_id>/` plus `reports/dev_log.csv` for development evaluation outputs, and declares Platform Contract v5 in `scripts/platform_channels.py`. That Python registry is mirrored by `platform/src/data/channels.ts`; parity has an existing test. Data archives and checkpoints may be external or gitignored, so a clean checkout cannot assume they are present. `scripts/eval_dev.py` owns the current development-evaluation protocol and metric definitions; the Inspector must read its outputs, not run or reinterpret the protocol. Two parallel OpenSpec changes define additional, independent evidence lineages: `benchmark-latent-reconstruction-prediction-architectures` writes experiment registries/manifests and outputs under `reports/architecture_benchmark/`, while `regional-ssl-representation-evaluation` writes pretraining, transfer, retrieval, generalization, and gate outputs under `reports/regional_representation/`. The benchmark's A1–A10 × suppression matrix and the capstone's candidate-screening/B1–B5/task ladders are not interchangeable, and the capstone explicitly does not depend on the broad benchmark.

## Goals / Non-Goals

**Goals:** define a safe boundary between configured source roots and Inspector-owned cache/report storage; keep format readers independently optional; make scans deterministic, incremental, and recoverable; and make QA/evaluation/readiness findings traceable to source artifact identities.

**Non-Goals:** editing pipeline or Platform outputs, running training/evaluation, serving arbitrary files, automatically exporting data, or replacing Platform contracts and existing validators.

## Decisions

1. **One modular Python application, no added service or frontend toolchain.** `tools/inspector/app.py` owns CLI/config loading, server startup, and report-only/refresh modes. Internal packages separate `core`, `adapters`, `validation`, `evaluation`, `visualization`, `reporting`, and static `ui`. A `ThreadingHTTPServer` serves only fixed UI assets and a small JSON API. No arbitrary filesystem/static route is exposed. Alternatives: a separate backend/frontend stack (more operational dependencies) or importing Platform React code (couples to build/runtime); both conflict with the local standalone contract.

2. **Configuration anchored to the repository, not the process working directory.** Resolve the repo root from the app's source location; resolve configured relative input and output paths from that root. Explicit absolute paths are permitted for external archives. Reject a configured non-loopback bind address. For API access, expose opaque artifact IDs and resolve each only against configured roots; reject traversal and symlink resolution outside a root. This avoids route parameters becoming filesystem paths.

3. **Versioned manifest and metadata-first incremental scan.** Use a documented JSON manifest schema as the canonical portable artifact inventory. Use SQLite (stdlib) for cache keys, normalized result metadata, and scan bookkeeping; SQLite is disposable cache, not the source of truth. File fingerprints include root-relative identity, size, and `mtime_ns`; hash small files when configured, while large files and directory stores use bounded metadata signatures. For compound stores such as Zarr, treat the store as one artifact and avoid recursively reading array contents. Compare metadata before and after adapter inspection; unstable/unreadable artifacts become `INCOMPLETE`/`ERROR` and are retried only on a later manual refresh. Serialize refreshes with one process lock. Each completed scan gets a new immutable history snapshot; `latest/` is a replaceable convenience view, never the sole record.

4. **Adapters load dependencies on demand and never execute model artifacts.** JSON/CSV/manifest parsing uses the standard library. NPZ and numerical summaries use NumPy only when available; Parquet, Zarr, GeoJSON geometry checks, and GeoTIFF metadata use their appropriate optional ecosystem readers. A missing package yields an explicit `UNSUPPORTED`/reader-unavailable result, not a startup failure. Checkpoint inspection reads filenames and safe sidecars; `.pt` is never unpickled and safetensors support is metadata-only unless a safe reader is available. Alternatives: make every dependency mandatory (unnecessary for basic inventory) or implement every parser in pure Python (unsafe/incomplete for scientific formats).

5. **Reuse existing scientific definitions and evidence.** Import the Python channel/score registry from `scripts/platform_channels.py` for ranges and names, with explicit error reporting if unavailable; do not copy its values into Inspector code. Keep the v5 contract version aligned through tests rather than making the TypeScript app a runtime dependency. Load existing evaluation JSON/CSV and preserve protocol/split/run/seed provenance. Only compute descriptive QA statistics; do not recompute detection metrics or use Test results to tune thresholds/rank models. Comparison eligibility requires compatible recorded protocol and evaluation context.

6. **Treat the three evaluation output families as separate, versioned dialects.** Keep adapters for current dev evaluations (`reports/dev/`, `reports/dev_log.csv`), broad architecture-benchmark outputs (`reports/architecture_benchmark/`, experiment registry state and per-cell manifest), and capstone outputs (`reports/regional_representation/`, pretraining/transfer/retrieval/generalization/gate records). Normalize only shared envelope fields (study ID, artifact type, schema version, protocol, run/seed, split/data hashes, status, metric name/value, evidence class); preserve original artifact paths and unknown fields. Never flatten benchmark A1–A10/suppression cells into the capstone B1–B5/task ladders, infer that one study gates the other, or combine them into cross-study rankings. Handle `near_matches` as descriptive only and keep capstone L-rung and evidence-class metadata visible.

7. **Respect locked-test isolation as an ingestion boundary.** Use declared split manifests and report metadata to classify test-bearing artifacts before opening payloads. When an artifact contains locked-test observations, only inventory its path/size/mtime and manifest-level split/hash metadata; do not sample its rows, compute quality statistics, or use test metrics for ranking, gate summaries, or threshold selection. If split membership cannot be established, mark the artifact `RESTRICTED/UNKNOWN_SPLIT` and omit value-level inspection by default. Display metrics already recorded in reports only when the report declares an allowed development/validation protocol; otherwise label them restricted and do not aggregate them. This is stricter than a generic file-browser default and preserves the existing `model-development-protocol` test-isolation requirement.

8. **Read-only API with a narrow write capability.** GET endpoints return manifest-derived inventory, reports, or map data. `POST /api/refresh` starts or reports the status of one scan; filesystem writes are confined to the configured Inspector output directory (SQLite, JSON/HTML, logs). There are no upload, delete, export-to-Platform, or arbitrary file-read endpoints. Escape display strings using DOM text APIs and JSON encoding; do not interpolate artifact values as HTML.

9. **Offline-first UI with graceful optional visualizations.** Static HTML/CSS/Vanilla JS ships in the Inspector. Plotly/Leaflet assets are loaded only from local vendored files when present; if absent, tables and textual summaries continue to work and the relevant view reports the missing visualization dependency. No remote basemap/CDN request is required for core functionality; if a basemap is offered, it must be opt-in and clearly documented as network-dependent. The selected-farm time series uses a local SVG fallback and actual payload dates. For the potentially large Platform series JSON, use an optional streaming parser to read only a requested farm; do not parse the whole archive into memory. Draw channel timelines from actual registry-defined index values, and overlay markers only for stored v5 `stressFlag == "suspected_stress"` observations, retaining `stressFlagModel`, split and channel provenance for details. Do not infer flags from NDVI or another threshold. Exclude `test` observations before returning timeline values; if split tags, flags, dates, or the optional streaming reader are unavailable, show an explicit unavailable state. Never assume a fixed 538-date axis.

10. **Independent artifact and evidence categories.** Discovery classifies by observed structure/path hints into dataset, preprocessing, phenology, baseline, SSL training, checkpoint, evaluation, validation, and Platform-export categories; uncertain categories remain `unknown` with the evidence/rule recorded. Readiness checks are individually critical/non-critical, with an overall BLOCKED state only for critical FAILs. Synthetic sensitivity, proxy agreement, and temporal/spatial generalization remain separate evidence classes.

## Risks / Trade-offs

- [Large recursive discovery can be slow or noisy] → Scan configured roots with explicit exclusions, recognize compound directory artifacts, use metadata fingerprints, and expose scan progress/counts; do not hash archive contents by default.
- [Metadata fingerprints can miss content changes that preserve size and mtime] → Offer targeted/full hashing for small artifacts and an explicit force-rescan option; report the fingerprint strategy in every scan.
- [Optional packages produce different coverage across machines] → Mark reader availability per artifact and keep manifest/schema/API tests independent of optional packages; add real-data tests only for the optional-reader environment.
- [Platform contract evolves] → Read Python registry values dynamically and test parity/version expectations; fail readiness transparently rather than falling back to hardcoded values.
- [Inspector results could be mistaken for scientific evidence] → Label descriptive QA, benchmark, proxy, and generalization evidence separately and include source/protocol provenance.
- [Local HTTP server may still be exposed by an unsafe bind/configuration] → Enforce loopback at startup, use no CORS, reject non-loopback hosts, and test path traversal and HTML-injection cases.

## Migration Plan

No migration of research artifacts or existing Platform payloads is required. Add the Inspector alongside existing scripts. The first invocation creates only its configured cache/output area; deleting that area is a supported cache reset and does not affect source files. Existing pipeline commands and output formats remain unchanged. Rollback consists of stopping the local server and removing only Inspector-owned outputs.
